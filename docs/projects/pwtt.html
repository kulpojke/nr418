Project Summary

The purpose of this project is to determine whether the Pixel-Wise T-Test (PWTT), originally developed by Ollie Ballinger, for damage detection in war zones, can be adapted to post-fire structure-damage screening in the wildland-urban interface.

PWTT detects abrupt changes in Synthetic Aperture Radar (SAR) backscatter from the Sentinel-1 satellites. It does not directly see damage. In urban warfare, abrupt SAR change near buildings is often a reasonable proxy for structural destruction. In WUI fires, the interpretation is less direct because houses, trees, shrubs, vehicles, fences, and bare ground are often mixed inside the same 10 m Sentinel-1 pixels.

This project will use Google Earth Engine. This is the most practical way to avoid building a local Sentinel-1 processing pipeline, which is beyond what is reasonable to expect in this course. This is being carried out, not necessarily to prove that radar can replace visual interpretation, or deep learning algorithms, but rather to test whether this simple and easily reproducible change statistic can help identify buildings or neighborhoods that should receive closer review after a wildfire.

This makes the wildfire application interesting because:

  • Burned vegetation near a house may be correlated with structure loss.
  • Burned vegetation near a house may create false positives.
  • Small homes may occupy less than one Sentinel-1 pixel.
  • Tree canopy can obscure or dominate the radar response.
  • Suppression activity, debris removal, wet soil, and post-fire cleanup can also change backscatter.

The study question is:

Can the Pixel-Wise T-Test identify burned or destroyed structures in a context where they are surrounded by other abrupt post-fire changes, e.g. burned vegetation?

Learning Goals

By the end of the project, students should be able to:

  • Explain the PWTT algorithm in plain language.
  • Run a reproducible Earth Engine damage-detection workflow.
  • Choose defensible pre-fire and post-fire time windows.
  • Attach raster change scores to building footprints.
  • Evaluate precision, recall, false positives, and false negatives against reference labels.
  • Explain how WUI vegetation complicates building-damage interpretation.
  • Make a clear recommendation about whether PWTT is useful for wildfire response.

Recommended Study Design

Select three to five wildfires and corresponding AOIs in WUI areas with known structure damage. Good candidates are events with public structure-damage maps, or well-documented post-fire imagery that you can annotate. I will help this.

Minimum scope:

  • three wildfires.
  • Three communities or bounded WUI AOIs.
  • Approximately 500-5,000 building footprints.
  • One reference label set for validation.

The event should have enough damaged and undamaged buildings to make precision and recall meaningful. Avoid AOIs where nearly every building burned or where almost no buildings burned (A ~ 50/50 split would be ideal).

You can use the code from the GitHub repo as a starting point. Make reasonable changes such as renaming variables in your notebook or comments so the workflow refers to fire dates rather than war dates.

Stratification of Data

Stratification should be based on pre-fire vegetation and land-cover context, not on the PWTT output itself. The goal is to ask where PWTT works well or fails and why. For example, are false positives concentrated around intact houses with burned vegetation nearby.

Create one table with one row per building (buildings from all fires/AOIs are pooled here). Before running the final accuracy assessment, attach context variables to each building footprint:

building_id
damage_label
PWTT_T_mean
PWTT_T_max
PWTT_ring_10_30m
pre_fire_tree_cover_30m
pre_fire_NDVI_30m
landcover_class
dNBR_30m
prediction

Determine vegetation characteristics within rings around each (labeled) building. You can decide on the ring size. Some suggestions to consider:

  • Building footprint: likely structure signal.
  • 0-10 m ring: immediate defensible-space context (and ~ pixel size).
  • 10-30 m ring: near-structure vegetation and parcel fuels.
  • 30-100 m ring: neighborhood fuel context.

Then divide buildings into a small number of pre-fire context classes (and join to table discussed above). Keep the categories simple enough that each group still has enough damaged and undamaged buildings for evaluation, e.g.:

low vegetation near building
moderate vegetation near building
high vegetation near building
tree-dominated
shrub-dominated
grass-dominated
dense built-up

For each stratum, report precision, recall, F1, and the number of damaged and undamaged buildings. The writeup should explicitly compare error patterns across strata. For example, if precision drops sharply in high-tree-cover parcels, that is evidence that PWTT is responding to vegetation change as well as structure change.

Data Sources

Sentinel-1

Use Earth Engine’s COPERNICUS/S1_GRD_FLOAT collection through the PWTT code. Earth Engine provides calibrated, orthorectified Sentinel-1 GRD imagery and metadata making it easy to filter and use.

Recommended settings:

  • Polarizations: VV and VH.
  • Instrument mode: IW.

Reference Labels

Validation labels may come from:

  • Official structure-damage inspections.
  • Manually interpreting high-resolution pre/post imagery.
  • Existing disaster datasets such as xBD, if the selected fire is included.

Every label must distinguish at least:

destroyed_or_major_damage
not_destroyed
uncertain
not_visible
footprint_mismatch

For model evaluation, collapse labels to binary (destroyed, not destroyed) only after removing or separately reporting uncertain, not_visible, and footprint_mismatch.

Modify the Urban Mask

The PWTT code masks results using Dynamic World built probability. This is reasonable for dense urban battle damage but not likely to work well in WUI settings.

  • Try changing the threshold for Dynamic World built probability so that does not discard mixed vegetation-building pixels near homes.
  • Try making a mask(or masks) based on density of structures in the buildings layer.

Also calculate a nearby vegetation/context score:

T_ring_10_30m

pre_fire_tree_or_vegetation_fraction
distance_to_fire_perimeter

The ring statistic is important because it helps distinguish “the building changed” from “the vegetation around the building changed.”

5. Choose Thresholds

Do not assume the battle-damage threshold works for wildfire.

Evaluate at least four thresholds:

T > 2.0
T > 3.3
T > 4.0
T > 5.0

Then choose a recommended wildfire threshold based on the precision-recall tradeoff. For screening, high recall may be acceptable. For public damage counts, precision matters more.

Validation

Compare predictions to reference labels at the building level.

Report:

  • Confusion matrix.
  • Precision.
  • Recall.
  • F1.
  • AUC or precision-recall curve if using continuous T_statistic.
  • Accuracy by building size class.
  • Accuracy by vegetation context class.
  • At least 10 mapped false positives and 10 mapped false negatives. ( As an Appendix)

For the false positives, classify likely causes:

burned vegetation near intact building
building footprint offset
small ancillary structure
post-fire cleanup or debris movement
shadow/layover/topography
actual damage missed in reference labels
other_or_unknown
